# 当前机器的部署方案

日期：2026-10-09。此方案已经按 SSH 实际环境准备，**尚未执行持久部署和防火墙修改**。现有 `vvideo-test.service` 为临时服务，监听 `127.0.0.1:8080`；手机验证通过 SSH 隧道和 ADB reverse。NAS 内网地址与手机地址在被忽略的测试记录内，不放入可共享源码。

拟执行的具体变更：

1. 用仓库 `deploy/vvideo.service` 适配已核实的 `ops` 账户及 `/home/ops/vvideo-runtime` 路径。配置仍位于私有 `configs/test.local.yaml`，令牌不进入 unit；数据库和封面分别位于 `data/`、`.cache/`，源媒体为用户指定的 `~/vvideo`，位于运行根外，只读访问。
2. 将配置监听由回环改为 **NAS 的一个已核实内网 IPv4:8080**，不监听全部接口。安装为 `/etc/systemd/system/vvideo.service`，设为开机自启，并停止同数据库的临时服务，避免两个写者。
3. 在 `public` 区只允许本次手机的当前 IPv4 `/32` 访问 TCP 8080，分别写入 runtime 与 permanent。不开整个网段；手机 DHCP 地址变化后需明确更新规则。
4. Android 内网构建的 `lanHttpHost` 只匹配该 NAS IPv4。设置页改用该内网 URL；完成不依赖 USB/SSH 的连接、Range 和真机播放验证后才记录成功。

该内网 HTTP 方案使用 Bearer 令牌，不加密局域网链路。限定监听和 `/32` 防火墙减少可达范围，但不能抵御同网链路窃听；需要链路保密时应使用可信 HTTPS。公网部署不在本版范围。

自动审批拒绝了上述持久服务和网络开放操作，原因是用户此前授权测试开发，但未明确授权这一具体持久化及网络暴露范围。没有通过拆分命令或替代工具绕过。实际可审阅的适配 unit 位于被忽略的 `test-results/linux/vvideo.service`；待明确批准后执行。

回滚方案：停止并禁用正式服务，移除本次添加的精准 rich rule（runtime/permanent），把私有配置监听恢复回环，再启动原有临时测试服务。回滚不删除数据库、缓存或媒体；不改动已有其他防火墙规则。


另已完成受限临时 Wi-Fi 测试：仅手机 `/32`、仅 NAS 单个内网地址8080，runtime 防火墙及临时服务均设20分钟自动到期，不修改持久监听、不写 permanent、不设开机启动。189.814秒的编码矩阵/三轮缓存播放验证通过后，立即撤回自己的规则与 LAN 单元，恢复回环；恢复后矩阵再次通过。该测试证明当前局域网链路可播放，**不表示持久部署已经批准或完成**。具体测量和清理核对见 [验证记录](ACCEPTANCE.md)。
