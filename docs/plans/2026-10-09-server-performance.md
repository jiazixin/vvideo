# 服务端大媒体库性能实施计划

日期：2026-10-09。执行对象：后续使用 **6.1 sol** 的实现任务。

**本计划保留实施步骤与测试契约；首版已有 Go 行为、恢复与合成规模测试。实际运行范围和未测场景见 [验证记录](../ACCEPTANCE.md)，不能把下列所有预期逐项视为已通过。** 本计划覆盖扫描/存储及与播放的交界；Android 另按第一版实现计划和设计验收。

目标：在约 13 万视频、38 万图片的文件夹媒体库上，以受控资源完成发现和增量处理，保留可靠索引，避免后台工作显著干扰原画播放。总量来自用户估计，目标 NAS、目录分布与存储性能尚未核实。

规范入口：[AGENTS.md](../../AGENTS.md)、[DESIGN.md](../DESIGN.md)、[IMPLEMENTATION.md](../IMPLEMENTATION.md)。提取证据：[性能决策](../decisions/2026-10-09-scan-storage-performance.md)。参考项目可删除，执行本计划不需要它的文件或数据库。

## 执行方式

- 先读取现有工作区；已有实现优先扩展，不照计划再生成第二套模块。下列文件均是**拟创建或修改位置**，最终按真实职责合并，禁止空包与占位测试。
- 写任何 Go 源码/测试前执行 `use-modern-go`；核实兼容 Go/SQLite 驱动版本，不直接复制参考项目版本。可执行代码适用检查通过后按 AGENTS 执行 `open-code-review`。
- 每阶段先写下面指定的行为测试，运行并确认因缺少该行为失败，再实现最小正确路径、通过测试和必要竞态检查。编译错误只能说明接口未齐，不能代替测试捕获行为缺陷；新接口补齐后须确认断言能识别故障。
- 测试只能访问临时库、合成夹具或已授权样本，不读取私有配置、不改源媒体，不为跑分开启正式库不允许的 PRAGMA。正常测试不创建几十万个实体文件。
- 指标、基准数据和测试报告留在被忽略的 `test-results/`；真正执行后才创建 `docs/ACCEPTANCE.md`，记录命令、范围、结果与未执行项。当前真实命令与验证范围见两个 README 和验证记录；下方拟议基准未全部实现。

## P0：建立可测的最小基础

拟涉及：`go.mod`、`cmd/vvideo/main.go`、`internal/config/`、`internal/scanner/metrics.go`、同包 `*_test.go`；集成夹具放 `tests/`。

1. 初始化真实 Go 模块并核实工具链；实现当前 YAML 契约及 CFG-01 至 CFG-14，不能复活已删除的配置字段。服务可正确加载配置、拒绝非法值并退出，日志不泄露 token。
2. 定义最小测试接缝：分页目录读取/属性读取、时钟、工具执行器、事务故障点及指标接收器。生产实现直接连接实际能力；不要为测试搭一个通用插件框架。
3. 建立临时目录/临时 SQLite 夹具，保证清理与错误传播；区分 schema 构建、数据生成、预热与被测阶段。
4. 指标必须能统计当前并发、页长度、业务行写入、事务提交、工具调用和未完成任务；性能直方图有界，不能留每个文件的所有采样。

完成条件：普通测试能控制 I/O 与时钟，能确定性制造“慢文件系统但 DB 正常”的场景，配置与设计一致。

## P1：SQLite 连接与批量写入

拟涉及：`internal/storage/store.go`、`writer.go`、`store_test.go`、`writer_test.go`；`internal/storage/schema.go` 中的内置初始化 SQL；`internal/library/` 的最小媒体/目录结构。

先实现 T-01、T-02、T-03、T-04。然后：

1. 建立本地 WAL/FULL 正式库，单 writer 与 4 个强制只读连接，验证所有新连接的外键、超时和读写权限；数据库结构版本与初始化/迁移失败路径明确。
2. 提供 context 感知的有限写入入口，记录等待/执行/commit，写回调不能包含文件 I/O。事务内准备语句并复用，写失败回滚。
3. 构建批次 B=128，分别计数实际提交记录与事务；计数和任务状态更新同事务完成。不要将“修改行数”与“执行语句条数”混淆。
4. 写批量基准，对比逐行事务和 32/128/512 行批次，但逐行方案只保留在测试比较中。相同数据、索引、驱动、FULL 设置、磁盘和缓存条件，报告写吞吐及最长事务。

完成条件：真实 SQLite 验证原子性、只读池与取消；批量路径明显减少提交次数，没有靠丢记录或降低持久性获得结果。不规定跨机器统一加速倍数。

## P2：有界目录遍历与属性采集

拟涉及：`internal/scanner/walk.go`、`metadata.go`、`filesystem_linux.go`、`walk_test.go`、`metadata_test.go`。

先实现 T-05 至 T-09。然后：

1. 一个协调者使用 `ReadDir(B)`，属性读取共用 `scan.parallel` worker。隐藏项/ignore 及目录边界检查位于正确阶段；不能只按字符串前缀判断目录包含关系。
2. 分页结果按输入槽位保存，失败与取消停止继续派发，并等待在途 worker 安全退出；目录句柄生命周期覆盖全部读取。
3. 逐层打开并核对根/目录身份，避免符号链接切换逃出媒体根。注入慢 stat 时不得持有正式库写事务或全局业务锁。
4. 单轮互斥、冻结本轮范围与 cron 行为采用设计规定。首版不并行遍历多个目录，子目录用 ID 游标和有界深度栈，不返回全量子目录数组。
5. 生产文件系统能力以 Linux 为准；如果开发机器是 macOS，仅使用显式的测试适配和编译边界，不声称本机测试代替 Linux 运行。

完成条件：页、并发、取消后在途数量和句柄都可验证；枚举未读完时不会返回“完整成功”。

## P3：暂存比较、增量发布和恢复

拟涉及：`internal/scanner/stage.go`、`scan.go`、`health_linux.go`、相应测试；`internal/library/scan_index.go`、`scan_index_test.go`；相关迁移。

先实现 T-10 至 T-16。然后：

1. 一轮复用一个受管磁盘暂存库，baseline 与双遍观测分页保存/比较；不同目录重置状态，失败或取消后的复用不能带入旧记录。
2. 先完成观测与比较，再分页构建不可见目录代。无变化只更新目录/轮次摘要；不逐文件更新 last_seen，不改变稳定 ID、内容版本或目录代。
3. 发布时校验基线、路径链与根；差异用索引定位，发布失败整个可见状态保留。分别测构建、发布及旧代回收，不能只报告总时间。
4. 每个根独立保存轮次成功/失败和缺失候选；只有完整健康轮次推进两次连续确认，排除及配置移除不作为缺失。根部分失败仍保留其他成功目录的新增/变更。
5. 中断构建与未发布任务具备可识别标记；启动或后台分批回收。清理每批重新检查发布状态及引用，不能删除刚变为有效的数据。
6. 保存稳定性任务的两个观测与时间，至少间隔 60 秒，使用假时钟测试；不能给全库每个文件睡眠或创建 timer/goroutine。

完成条件：首扫、未变复扫、小比例变化、失败恢复都正确；基线版本冲突不会覆盖新结果；旧索引在慢扫描期间可用。超大目录发布事务成本必须有单独结果，不能用“原子切代很快”代替测量。

## P4：持久任务与昂贵工作分离

拟涉及：`internal/jobs/queue.go`、`worker.go`、`queue_test.go`、`worker_test.go`；`internal/library/probe.go` 与测试；`internal/thumbnail/` 的任务衔接与测试。

先实现 T-17 至 T-20。然后：

1. 索引构建批次可靠写入待处理意图，发布后可认领。任务唯一键包含媒体 ID、内容版本、任务类型及参数；重复扫描和重启不会重复生成同一有效任务。
2. 数据库保留积压、内存只保留有界窗口。稳定性复核、元信息提取与封面生成不占扫描 worker 或 DB 写事务。
3. 先用可控假工具执行器验证并发/错误/恢复，再使用隔离短视频和图片执行真实工具测试。工具进程数、解码线程、超时分别控制。
4. 旧版本任务完成时拒绝写入新版本；未变且成功处理的媒体不重复执行。失败有上限，缓存被淘汰不等于媒体需要重新建库。
5. 同批探测元信息更新排序键与目录修订；不每文件重建目录代，也不为每个结果广播整目录。扫描发布与探测写入交错的场景必须正确。

完成条件：扫描统计能在工具阻塞时继续；“索引已发现”“元信息就绪”“封面就绪”状态分开，重启不漏任务，不出现旧封面覆盖新内容。

## P5：分页、锚点、清理与统计成本

拟涉及：`internal/library/list.go`、`anchor.go`、`list_test.go`、`query_plan_test.go`；`internal/scanner/cleanup.go` 与测试；`internal/thumbnail/` 容量账目；必要迁移。

先实现 T-21 至 T-24。然后：

1. 为当前产品支持的时间/mtime/名称排序建立正确的索引与稳定 ID 次序，游标携带目录修订。默认拍摄时间按设计回退，不推测时区。
2. 从媒体锚点索引取附近页；十项分组定位不能暗中使用深 OFFSET 或统计全部前缀。客户端遇到修订变化以锚点重定位。
3. 清理按候选或目录代索引分页，不每小目录重扫全部 entries；外键反向索引也要检查。
4. 容量、目录统计使用提交后增量账目或有界修订缓存，不把全库统计放在列表/状态接口热路径。
5. 单个 HTTP 页完成 DB 读取后再发送，关闭 rows/事务；验证读池耗尽时取消可返回，writer 不被占用。

完成条件：第一页、深处页、深处恢复均是有限输出和索引范围查询；大表上大量空目录清理不会反复扫描无关记录。

## P6：后台让步、真实规模与回归基线

拟涉及：`internal/jobs/priority.go`、`internal/scanner/schedule_test.go`、`internal/streaming/` 的活动登记；`tests/scan_playback_test.go`、`tests/library_scale_test.go`、`tests/filesystem_scale_large_test.go`。

先实现 T-25 至 T-28，再按下文分层压测：

1. 原字节请求进入/结束更新有界活动计数，含预加载；在派发新后台页/任务前检查活动与 10 秒冷却。取消请求也必须释放活动计数。
2. 已在途批次收尾；暂停不占写事务或共享锁。恢复时核对根和目录快照，过期观测重做，cron 不积压。
3. 本机合成索引与真实文件分开测试，再在已授权的 NAS 媒体上只读验证；小文件的扫描结果不可代替真实 ffprobe/抽帧成本。
4. 拿到首个真实服务/播放闭环后，冻结目标环境的列表 p95/p99、首字节/拖动、扫描与工具吞吐、最长 writer 占用、RSS/WAL/暂存上限及允许回归范围。没有冻结与通过这些基线，此阶段不能标记完成。
5. Android 实现接入后，以 iQOO 12 Pro 复验扫描竞争下的 UI/首帧/缓冲，沿用 DESIGN 的高刷门槛。只跑 HTTP Range 基准不能宣称手机播放流畅。

完成条件：算法与故障门槛通过，目标机器基线有实际记录，后台负载下播放达标；未具备 NAS/真机的部分明确列为未验收，不伪造时间或内存指标。

| T-26 `TestResumeRevalidatesAndCronDoesNotOverlap` | 播放暂停扫描期间源目录变更，多次 cron 触发（2026-10-20 起扫描不因播放暂停，暂停部分不再适用） | 唯一轮次无积压；恢复不发布过时快照；没有锁/事务跨暂停 |
| T-27 `TestScaleMixedLibrary` | 下表 S1/S2/S3，首次/未变/小改三种轮次 | 精确数量、无重复任务、版本正确；多次失败恢复后 integrity_check=ok、foreign_key_check 无结果 |
| T-28 `TestScaleRangeDuringBackgroundWork` | 后台扫描/工具/清理，与首段、尾段、seek Range 请求并发 | 字节、206/416/取消/版本匹配正确；延迟与吞吐报告完整，实际播放另做真机验收 |

取消/并发测试优先使用 barrier 与假时钟决定顺序，超时仅作防死锁保护，不靠极短 sleep 赌调度。子进程退出可验证进程崩溃恢复，**不能代替真实断电耐久性测试**。

## 分层规模与性能实验

| 层级 | 数据 / 场景 | 目的及边界 |
| --- | --- | --- |
| 普通测试 | 空目录、257 项、嵌套/符号链接、少量合成媒体、故障注入 | CI 快速验证行为，不依赖真实 NAS |
| S1：合成 DB | 510,000 媒体行，视频/图片比例 130,000/380,000；分散目录与单超大目录各一组 | 检查索引、分页、清理、事务；不代表文件系统或解码吞吐 |
| S2：属性延迟 | 512 / 5,120 项，注入 0/2/10 ms 读取延迟；P=1/2/4/8 | 看并发、收尾、内存和 DB 非阻塞；模拟延迟不是 SMB 实测 |
| S3：真实文件 | 510,000 个临时小文件；分散到 100 个叶目录；单超大目录和大量空子目录另测 | 测真实枚举及索引；单独计时夹具生成，不自动进入普通测试 |
| S4：媒体处理 | 小批有效横/竖屏、短视频、长 GOP、尾 moov、图片 EXIF、损坏文件 | 真正测 ffprobe/FFmpeg 和版本变化；不把伪扩展名小文件当可播放样本 |
| S5：目标 NAS | 先代表性目录，再完整已授权根；索引/暂存本地，媒体原位只读 | 记录挂载协议/选项、网络、磁盘与目录分布；独立测首次、未变、小比例变化 |
| S6：竞争与长期 | 浏览/seek/预取 + 扫描/探测/抽帧/清理，至少 30 分钟 | 测播放优先、资源回收、WAL/暂存增长与真机流畅度 |

单超大目录 S1 至少测“新增 1 项”“修改 1%”“大量缺失候选”三种变化；S3 可先用 100,000 项发现算法问题，再到完整规模。大量子目录场景验证遍历栈/游标，不能只测很多文件但很少目录。

B=32/128/512 的写入实验、P 的属性实验分开进行，避免同时改变多个变量。参考项目的 128/4 是经验起点，VVideo 示例 `scan.parallel=2` 保持不变；最优值以目标存储与播放竞争结果决定。

同环境本机基准至少 5 次，NAS 场景至少 3 次，报告全部样本、中位数及尾延迟；记录冷/暖缓存，不能将后跑暖缓存当算法加速。默认不执行全机 drop_caches；未控制 OS/NAS 缓存时明确标注，不声称冷缓存。计时测试不与 race、构建或其他规模测试争用资源。

## 实现后才可使用的命令

以下命令只有对应模块、包、测试与 build tag 已实现后才成立。先从测试清单确认测试存在，禁止将 `[no tests to run]` 当通过。Linux 专用回归需 Linux 运行；交叉编译不代替执行。

```sh
go test ./...
go vet ./...
go test -race ./internal/scanner ./internal/library ./internal/jobs ./internal/storage
go test -tags=scale -run '^TestScale' -count=1 -p=1 ./tests
go test -tags=scale_large -run '^TestScaleFilesystem' -count=1 -p=1 ./tests
go test -run '^$' -bench '^BenchmarkBatchWrite$' -benchmem -count=5 ./internal/storage
go test -run '^$' -bench '^BenchmarkScanUnchanged$' -benchmem -count=5 ./internal/scanner
```

`scale_large` 专门隔离昂贵实体文件夹具；测试名和上述过滤器必须一起落地。NAS 与真机测试按实际工程补充入口、前置条件和样本选择，不能现在编造 Gradle 或部署命令。格式、模块校验和构建检查随实际工程配置执行。
