# 初版真机数值基线

冻结时间：2026-10-09 03:44（Asia/Shanghai），在非调试首次播放闭环之后、冷/暖/预取三轮统计和 4K 测量之前。此表只适用于本次授权合成样本、iQOO 12 Pro、USB ADB reverse + SSH 到 Linux 的条件。真实 NAS、4K HDR/高码率用户样本和 Wi-Fi 必须补测，不能外推。

| 项目 | 本次冻结的门槛与范围 |
| --- | --- |
| 相册暖滑动 | 沿用 DESIGN：实际高刷下每轮正 frameOverrun 比例 ≤1%，无可复现的应用 >100 ms 停顿，至少三轮；不能改用平均 FPS |
| 首帧 | 每种冷磁盘/已有磁盘/确认预取场景各三轮；目标选定至匹配媒体首帧 p95 ≤750/500/500 ms，逐轮报告所有有效样本，错误不能剔除 |
| 拖动恢复 | 选定 75% 位置至 READY 且目标位置可播放的 p95 ≤1000 ms；首帧可见与 READY 分开记录，不将固定等待当作耗时测量 |
| 查询 | 本次 Linux 暖页/深处锚点查询 p95 ≤25 ms；HTTP 网络耗时另报，不能将 SQL 耗时当 Wi-Fi 端到端耗时 |
| 内存 | 至少 30 分钟混合播放，PSS ≤512 MiB；同时报告 Java/native/图形，不用托管堆代替全进程；前五分钟预热后不出现持续单调增长，最后五分钟与预热后五分钟 PSS 中位数增长 ≤25 MiB |
| 正确性 | 无应用崩溃、ANR/OOM、串音或版本混字节；长期测试自身构建和厂商冻结的失败另列，不能算通过 |

上述数值是项目针对第一版制定的门槛，不是 Android 官方标准。PSS 覆盖 4K 解码器和 Surface 的 native/图形成本；播放 32 MiB、图片 32 MiB 与预取 8 MiB 是各自内部预算，不等于总进程上限。首帧基线来自首次 13 个样本实测的数量级，再留下正常网络/解码波动空间，尚未宣称三种缓存场景通过。

若结果未达标，定位并修复同一路径后复跑，不上调此表以掩盖失败。记录具体 APK SHA-256、变体（混淆 profile 或未裁剪但非调试 device）、温度、有效刷新率、媒体特征和缓存条件；不同变体结果不能偷换。
